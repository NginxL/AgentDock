## 可重复测量

`python3 scripts/benchmarks/cancellation.py --runs 8000` 在临时数据库里生成已完成的运行记录，分别删除和恢复索引，对同一查询各测三次、取中位数。不会打开用户数据库。

2026-10-08，本机 Python 3.9.6、8,000 条记录：修复前 **2,235.211 ms**，修复后 **6.867 ms**（约 **325 倍**）。绝对时间随设备变化，不作为脆弱的单元测试门槛。

相关回归：`python3 -m unittest tests.test_store tests.test_account_runtime -q`，44 项通过。当前代码要求 Python 3.11+；前述 Python 3.9.6 数据是升级前留存的同机测量。

2026-10-09 使用 Python 3.13.14 复测同一 8,000 条记录：无索引 **1,972.807 ms**，有索引 **7.254 ms**（约 **272 倍**）。状态读取复测：完整快照 **42.982 ms / 5,175,933 字节**，无变化增量 **0.221 ms / 66 字节**。

## 状态读取与长任务

`python3 scripts/benchmarks/state_sync.py` 使用 8,000 条临时会话，比较五次读取的中位数：完整快照 48.247 ms / 5,175,933 字节，无变化的增量快照 0.172 ms / 66 字节。初次加载及服务重启仍返回完整快照；变更推送只携带版本号，客户端拉取变化的数据集合。会话事件继续使用独立事件流。

`Agent.run_timeout` 可设 30–86,400 秒；界面以分钟设置。留空使用服务配置 `run_timeout`（默认 900 秒）。客户端审批等待仍有独立的审批超时，取消一直有效。进度达到显示上限会记录 `output_truncated`，不会据此取消原生任务；单条损坏/超长协议行仍会拒绝。

405 项后端、213 项前端和生产构建通过。相关覆盖包括大输出最终结算、审批等待、删除并发、只读 WAL 快照、版本回滚、会话通知范围和分钟缓存。

## Codex 凭据写入核对

`python3 scripts/benchmarks/codex_auth_write.py --codex /path/to/codex` 只使用临时目录和虚构 API key，不使用真实登录。已安装的 Codex CLI 0.154.0 在该实验中保留 `auth.json` 符号链接并更新目标文件；当前 [官方文件存储实现](https://github.com/openai/codex/blob/main/codex-rs/login/src/auth/storage.rs) 使用截断写入。因此审查中“刷新必然替换链接”尚无证据支持。真实 OAuth 刷新仍待人工验收，设备登录路径保持原状。托管账号复制回写增加源文件指纹核对，拒绝覆盖并发登录。

## 结构与协议验证

423 项后端测试通过。路由表对每个执行入口集中检查执行开关，覆盖远端目录和任务输入的条件权限；公共错误脱离 Store，消除了混入类为了循环依赖而临时导入错误类型的情况。超过旧累计文本上限的 Codex / Claude 过程消息仍能保留最终回复。运行凭据有效期覆盖配置的最长执行及有界审批等待，结算仍立即撤销。

## 前端及规范

216 项前端测试和生产构建、423 项后端测试通过。工作台和项目任务按表单、列表、问题、设置和会话拆分，相关表单字段合并管理。704 条固定中英文文案使用命名词条，错误按稳定 code 翻译，兼容旧服务响应。模型、状态和统计请求交给 TanStack Query；账号代际及版本合并保留业务校验。CSS 拆分保持原始级联顺序。

Ruff 检查覆盖后端源码，格式检查覆盖源码、测试和脚本；mypy 严格检查错误类型、文本缓冲和运行参数对象，其余模块逐步增加类型。格式化单独提交，方便与行为修改分别审阅。`npm audit` 当前报告 0 项已知漏洞。

## 运行时与最终验证

Python 3.13.14 上 **430 项后端测试**、**216 项前端测试**及生产构建通过。Swift 的额度 23 项、提供方 13 项、桌面 31 项检查及凭据加密/IPC 检查通过，均未访问真实钥匙串或执行换号。Ruff、格式、渐进 mypy 通过。

新增启动回归发现标准库 HTTPServer 的反向 DNS 查询可能卡住本机及 SSH worker。已改为无 DNS 的回环服务，覆盖自动端口、Host/Origin、重复实例令牌保护和配置范围检查。删除外部清理同时释放数据库锁与调度器锁。

wheel 在全新虚拟环境安装后，前端、认证接口、自动端口及关闭通过。Apple Silicon 应用内置 Python，迁移后的后端启动及启动后签名完整性通过；没有启动桌面窗口、安装覆盖应用或切换账号。Apple Developer ID 公证需要发布凭据，Intel 构建和真实 CLI 工作流需由对应发布/验收环境执行。详见[分发与验证边界](DISTRIBUTION.md)。

初次状态加载仍为完整快照；增量按数据集合同步，未实现逐行分页。协议已拆分并共用底层通信与参数，模型、额度及清理仍保留服务特有逻辑。mypy 目前严格覆盖三个基础模块。这些边界不等于全量分页、所有服务同一套协议或全仓严格类型已经完成。
