## 可重复测量

`python3 scripts/benchmarks/cancellation.py --runs 8000` 在临时数据库里生成已完成的运行记录，分别删除和恢复索引，对同一查询各测三次、取中位数。不会打开用户数据库。

2026-10-08，本机 Python 3.9.6、8,000 条记录：修复前 **2,235.211 ms**，修复后 **6.867 ms**（约 **325 倍**）。绝对时间随设备变化，不作为脆弱的单元测试门槛。

相关回归：`python3 -m unittest tests.test_store tests.test_account_runtime -q`，44 项通过。

## 状态读取与长任务

`python3 scripts/benchmarks/state_sync.py` 使用 8,000 条临时会话，比较五次读取的中位数：完整快照 48.247 ms / 5,175,933 字节，无变化的增量快照 0.172 ms / 66 字节。初次加载及服务重启仍返回完整快照；变更推送只携带版本号，客户端拉取变化的数据集合。会话事件继续使用独立事件流。

`Agent.run_timeout` 可设 30–86,400 秒；界面以分钟设置。留空使用服务配置 `run_timeout`（默认 900 秒）。客户端审批等待仍有独立的审批超时，取消一直有效。进度达到显示上限会记录 `output_truncated`，不会据此取消原生任务；单条损坏/超长协议行仍会拒绝。

405 项后端、213 项前端和生产构建通过。相关覆盖包括大输出最终结算、审批等待、删除并发、只读 WAL 快照、版本回滚、会话通知范围和分钟缓存。

## Codex 凭据写入核对

`python3 scripts/benchmarks/codex_auth_write.py --codex /path/to/codex` 只使用临时目录和虚构 API key，不使用真实登录。已安装的 Codex CLI 0.154.0 在该实验中保留 `auth.json` 符号链接并更新目标文件；当前 [官方文件存储实现](https://github.com/openai/codex/blob/main/codex-rs/login/src/auth/storage.rs) 使用截断写入。因此审查中“刷新必然替换链接”尚无证据支持。真实 OAuth 刷新仍待人工验收，设备登录路径保持原状。托管账号复制回写增加源文件指纹核对，拒绝覆盖并发登录。

## 凭据与派工回归

418 项后端测试通过；新增覆盖实验开关升级默认值、旧换号策略不可绕过、ACP 刷新冲突与恢复、项目审批生命周期、批量历史连续性、记忆检索项目隔离，以及完成事件压缩后断点回放。ACP 模型发现使用持久恢复目录，临时工作目录清理不会删除未回写凭据；旧版遗留凭据与来源不同则保留双方并阻止覆盖。

## 结构与协议验证

423 项后端测试通过。路由表对每个执行入口集中检查执行开关，覆盖远端目录和任务输入的条件权限；公共错误脱离 Store，消除了混入类为了循环依赖而临时导入错误类型的情况。超过旧累计文本上限的 Codex / Claude 过程消息仍能保留最终回复。运行凭据有效期覆盖配置的最长执行及有界审批等待，结算仍立即撤销。
