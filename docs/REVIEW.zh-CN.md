## 实现状态

AgentDock 0.3 由 React 界面、Python 标准库服务和 SQLite 存储组成。任务由原生 Codex 与 Claude Code 进程执行；调度器保留原生会话标识，负责派发工作和回传结果。五个受限 MCP 工具提供协作和已审核的项目记忆。macOS 安装版内置独立额度程序，通过 `--probe` 提供去敏快照。

| 领域 | 已实现 | 验收边界 |
| --- | --- | --- |
| 界面 | 默认中文、英语切换、项目导航、原生会话状态、对话事件、任务派发、审批、共享记忆和额度摘要。 | 离线预览通过真实界面渲染虚构测试数据，不代表真实模型执行、订阅或额度已经可用。 |

| 协作 | 自动派发、按工作目录排队、原生会话续接、结果回传、重试去重、深度与运行次数上限、后代任务取消。 | 真实模型的委派行为和长时间协作需要实机验收。 |

| 额度 | Codex 与 Claude 的内置额度探测，超时与限流处理，未知、过期和错误状态，以及独立的手动订阅记录。 | 本机 Codex 查询和 Claude 本地快照读取通过；更多账号配置与官方用量页核对仍待验证。 |

## 提供商兼容性

| 提供商 | 本地核对版本 | 使用的协议契约 |
| --- | --- | --- |
| Codex | `codex-cli 0.154.0` | 导出的应用服务 JSON 模式及官方文档：`initialize`、`thread/start`、`thread/resume`、`turn/start`、审批请求、事件通知和 `turn/interrupt`。 |
| Claude Code | `2.1.283` | 原生命令行帮助与 Anthropic 公开的控制协议定义：`--print`、`--input-format stream-json`、`--output-format stream-json`、`--resume`、`--session-id`，以及标准输入输出上的权限请求。 |

以上是**协议契约核对版本**，不代表已完成端到端兼容性验收，也不代表所有版本通用的最低版本要求。Claude 适配器默认使用 `--permission-mode manual`，用户选择完全访问时使用 `bypassPermissions`，并保留 `--permission-prompt-tool stdio`。不支持参数时会报错，适配器不会自动扩大权限重试。认证由原生命令行客户端按其支持的本地配置处理。AgentDock 不强制要求 API 密钥，不导出提供商凭据，不修改登录状态，也不安装 Agent SDK。

“需要确认”模式下，Codex 使用本次运行拥有的应用服务进程，配置为 `workspace-write`、`untrusted` 命令审批和用户审核；仅新建或恢复 AgentDock 拥有的会话。Claude 使用人工审批权限模式，将权限提示发送给工作台；批准后只返回该次工具调用的原始输入，拒绝时不授予权限。原生客户端已有的策略和受管限制仍然生效。AgentDock 自身不提供独立的操作系统沙箱。

完全访问使用 Codex `danger-full-access` 与 `never`，或 Claude `bypassPermissions`。离线测试覆盖双提供方、本机和 SSH 传递、降低权限后续接原生会话、无效值、迁移默认值，以及模型不能修改权限。隔离的本机 CLI 初始化接受两种模式；Codex 返回的沙箱与审批策略符合设置。生产主机上的完全访问模型工具执行不属于该验证范围。

每轮前台任务结束后原生进程退出，原生对话保留供下次恢复。Claude 子进程环境设置 `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1`，按[官方环境变量说明](https://code.claude.com/docs/en/env-vars)禁用原生后台任务；此设置不修改用户全局环境，也不影响其他 Claude 进程。已登记 Agent 通过 AgentDock 调度器协作。这是会话续接，不是附加到已经运行的桌面或终端进程。额度展示与执行认证彼此独立：能读取额度快照，不代表已经确认该提供商可以执行任务。

官方协议资料：[Codex 应用服务](https://learn.chatgpt.com/docs/app-server)、[Claude Code 命令行](https://code.claude.com/docs/en/cli-reference)、[Anthropic 控制协议实现](https://github.com/anthropics/claude-agent-sdk-python/blob/main/src/claude_agent_sdk/_internal/query.py)。

本机 Codex 0.154.0 与 Claude Code 2.1.283 已验证独立存储中的两轮纯文本续聊、原生会话 ID 保持、模型标识回传、原客户端目录无新增测试会话，以及配置文件哈希不变。Claude 凭据存储覆盖默认 macOS 登录入口；Codex 覆盖文件凭据登录，只有钥匙串凭据的配置仍待验证。

## 隔离验证

后端检查使用临时 SQLite 数据库、模拟原生命令行的进程和模拟额度探测。调度集成测试使用临时回环 HTTP 接口及真实 MCP 桥接程序，但编程 Agent 均为确定性的本地测试程序，不涉及真实模型、提供商登录或在线额度接口。

前端检查使用模拟 DOM 与 HTTP 响应。生产构建校验 TypeScript 并生成静态资源。离线演示渲染虚构的项目、对话和额度数据，禁用执行、修改和提供商请求；该模式的截图仅展示界面。

Agent 配置检查覆盖表单内 SSH 登记与重试、连接复用、连接后的模型发现、收起后保留草稿，以及同名 Agent 的会话和额度隔离。菜单摘要按自定义名称展示，并兼容旧版额度快照。

运行位置切换测试覆盖两种服务的本机与 SSH 双向切换、排队及运行任务、原生会话续接、模型与权限默认值保留、显式及自动派工、多次切换、重启持久化，以及按原位置清理会话。测试使用确定性模拟程序，不向生产环境提交模型请求。

## 实机验收要求

真实执行需要作为独立步骤显式启用。在可信、可丢弃的工作目录中完成以下检查后，再将预览版用于日常工作：

1. 验证原生命令行客户端的认证和配置版本；每个提供商连续执行两轮任务，确认第二轮恢复同一原生对话。
2. 验证权限批准、拒绝、过期、取消与重启行为；确认排队任务取消后不会启动，未完成任务重启后不会重放。
3. 运行 Codex → Claude → Codex 协作和嵌套委派，确认原发送方在原会话中收到最终结果，重复委派受到上限约束。
4. 验证共享记忆提议审核、版本冲突和项目隔离；将真实剩余额度与重置时间同官方用量页面核对，覆盖失败和缓存过期状态。
5. 使用真实会话检查两种界面语言，确认错误、排队、审批、结果和未知额度状态清楚易懂，且不暴露凭据。

桌面启动、自动连接、退出清理及 Codex／Claude 真实额度读取已通过本机 macOS 验证。双提供方的两轮连续对话与 Token 用量事件已通过；更多账号、工具审批、长时间协作及与官方用量页的一致性仍待核对；既有会话导入尚未实现。安装器不注册后台服务、开机启动项或全局 MCP 配置，也不更改提供方登录状态。

## 0.3 增量验证

独立 Agent 建立与执行、项目记忆隔离、路径互斥、旧数据库迁移、模型与 effort 传递、真实用量事件、重复消息块、实时与历史去重、归档副本、日志追加与截断、空闲与未知 TPS 均有自动检查。原生额度检查覆盖源时间保留、未知重置时间、非法百分比及多组织快照拒绝。

本机实测 Codex 与 Claude 各连续两轮对话，第二轮恢复同一原生会话并正确保留测试标记；均收到 Token 用量事件。CLI 模型发现和 Claude Desktop 快照读取通过。自动测试均为离线 fixtures，实机检查不属于 CI。本机结果不代表所有模型、版本和账户兼容。
